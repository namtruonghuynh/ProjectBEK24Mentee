DTO
Mục đích: định nghĩa cấu trúc dữ liệu đầu vào từ client 
Signup: bao gồm (name, email, phone, password)
Signin: bao gồm (email, password)
Luồng xử lý của auth
Signup:
Kiểm tra về email có tồn tại chưa
Hash password sử dụng bcrypt với salt rounds =10 và không lưu plain text password vào DB
Tạo user mới và lưu vào DB với collection user
Trả về kết quả tạo user thành công
Signin:
Tìm user theo email
So sánh mật khẩu dùng bcrypt.compare() và không tiết lộ email hay password sai cụ thể
Tạo accessToken và refreshToken
Hash refreshToken và lưu vào DB  ( để verify khi refresh )
Trả về cả 2 token trong response body ( để cho client tự quản lý có thể lưu trong localstorage, sessionstorage,..)
Refresh:
Kiểm tra user tồn tại và refreshTokenHash có tồn tại trong DB không 
So sánh refreshToken từ client với hash trong DB
Nếu khớp sẽ tạo accessToken mới 
Trả về accessToken mới
Signout:
Yêu cầu accessToken 	
Xóa refreshTokenHash khỏi DB 
Trả về thông báo thành công
getTokens:
Tạo 2 Token song song

Access Token: 15 phút, dùng để xác thực API requests
Refresh Token: 7 ngày, dùng để lấy access token mới

Helper methods:


Mục đích của hash refreshToken, nếu DB bị leak thì không thể dùng refreshToken trực tiếp. Phải có refreshToken gốc mới verify được.
Strategies
Dùng để xác định cách lấy token và cách verify token. Được Guards gọi để kiểm tra authentication
AccessTokenStrategy: 
Lấy token từ  Header Authorization: Bearer <token>
Verify bằng: JWT_ACCESS_SECRET
Trả về { sub(userId) , email }
RefreshTokenStrategy: 
Lấy token từ Cookie refreshToken
Verify bằng: JWT_REFRESH_SECRET
Trả về { sub, email, refreshToken }
Guards
Bảo vệ routes, quyết định request có được phép truy cập hay không.
AccessTokenGuard: 
bảo vệ các api cần authentication
Lấy token từ header Authorization: Bearer <token>
Verify với JWT_ACCESS_SECRET
RefreshTokenGuard: 
Bảo vệ endpoint /auth/refresh
Lấy token từ cookie: refreshToken
Verify với JWT_REFRESH_SECRET
